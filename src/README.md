# Fruits & Légumes de Saison — Perchance generator

A French seasonal-produce app: 154 products (fruits, légumes, aromatiques) with kawaii avatars, scenic banners, a monthly calendar, local-eating info, and a Candy-Crush-style match-3 game whose tiles are the product avatars.

## Files

- `index.html` — app shell: CSS theme (Baloo 2, green/cream palette), 5 tabs (En ce moment / Almanach / Calendrier / Le Jeu / Local — they wrap onto two rows under 620px so none is ever cut off), detail overlay, the game markup (`#gameMap` level map + `#gamePlay` board/HUD/boosters), and `<script>` tags for data + app + levels + game (order matters only in that `levels.js` must load before `game.js`).
- `main.pjs` — `$meta` (title/description/tags) + `generateText = {import:ai-text-plugin}` (currently unused at runtime; kept for future AI features).
- `src/app.js` — view logic: home ("En ce moment" — hero with current month + in-season count, two CTAs "Voir le calendrier" + "Surprenez-moi !" (opens a random product), scrollable avatar strips per category + "Conservés" + rotating daily tip), almanach (full-text search over name/origin/category/group/description/scientific-name/family, accent-normalized via `normS`/`searchText`/`searchCache`, + 3 chip rows), calendar (month nav), detail page (banner + avatar + season strip + kcal + nutrition section when available + sections), local page, tab switching. State in a closure; renders to DOM via template strings. `window.App` not exposed; DOM ids drive everything.
- `src/game.js` — the game ("Match des Saisons"). One IIFE with two halves: a pure logic core (grid, objectives, gravity, cascades, `moveValue` heuristic) that can run "headless" for simulation, and a DOM render layer (absolutely-positioned tiles in `.blayer`s, jelly, crates, FX, WebAudio synth). Exposes `window.GAME = {ensureBoard, newGame, isReady, __debug}`. See "Le Jeu" below.
- `src/levels.js` — the 60 level definitions, generated deterministically (see "Le Jeu" below). Exposes `window.LEVELS = {total, get, tierName, tierOf, shapes}`.
- `src/data/products.js` — `window.PRODUCTS`, 154 items: `{n, cat (Fruit|Légume|Aromatique), group (saisonnier|exotique|ancien), origin, d (description), pc (choix/achat), cons (conservation), nut, kc (kcal), kcu, img (original photo refs — dead, unused), m (season months), mc (conservation months), nt (dead refs), always (exotics year-round), b[2] bienfaits, a[2] astuces, f (fait)}`.
- `src/data/local.js` — `window.LOCAL_HTML`, the "pourquoi manger local" page HTML.
- `src/data/avatars.js` — `window.AVATARS = {name: url}`, 154 kawaii mascots (512x512, plain pastel bg, family-styled).
- `src/data/banners.js` — `window.BANNERS = {name: url}`, 154 landscape banners (768x512) with coherent per-product backgrounds.
- `src/data/nutrition.js` — `window.NUTRITION = {name: {...}}`, nutrition + botanical data for **all 154 products**. Primary source: the official French reference table **Ciqual 2025 (Anses)** — license ouverte (raw: `scratch/sources/ciqual.xlsx`, parsed to `ciqual-full.json`). Keys: `k` kcal, `c` glucides, `p` protéines, `l` lipides, `s` sucres, `fib` fibres (g/100 g), plus optional minerals/vitamins `ca` (calcium), `fe` (fer), `mg` (magnésium), `kp` (potassium), `zn` (zinc), `vita` (vitamine A, µg), `betac` (bêta-carotène, µg), `vitc` (vitamine C, mg), `vitb9` (folates, µg), `vite` (vitamine E, mg); `sci` scientific name (manual additions for rows where Ciqual omits it); `f`/`o`/`g` famille/ordre/genre (fr) for the 41 fruits previously enriched from FruityVice; `src` = `"ciqual"` (140 products) or `"ref"` (14). The 14 `ref` products have no Ciqual raw entry (Amélanche, Aronia, Cornouille, Corossol, Kiwano, Longane, Maca, Mangoustan, Oca du Pérou, Ortie, Persil racine, Physalis, Pitaya, Tomatillo) — curated standard reference values + a few sensible Ciqual aliases (e.g. Aillet→ciboule, Cerise→"Ceriser" [Ciqual's own spelling], Cornichon→"au vinaigre", Chicon→Endive, Radicchio→Chicorée rouge, Salsifi→surgelé cru, Pâtisson→Courge, Jack be little/Patidou→Potimarron, Oignon nouveau→Oignon cru, Tétragone→cuite). Rendered in the detail page: tiles (Énergie if the product has no `kc`, Glucides, Sucres, Fibres, Protéines, Lipides) + bars, a "Points forts nutritionnels" chip row (top 3 nutrients ≥15 % of adult reference intake), botanical classification (Nom scientifique + Famille/Ordre/Genre when present), and the source credit (Ciqual vs FruityVice+référence).

## Le Jeu — "Match des Saisons" (match-3)

60 levels on an 8x8 board. Tile art is the product avatars (`AVATARS`), so every tile is a kawaii fruit/vegetable.

**Board & rules.** Orthogonal matches only (3 in a row/column) — diagonals are NOT matched. 4-in-a-row → striped `fruit rayé` (clears a line), 5 straight → golden `fruit doré` (3×3 blast), L/T → rainbow `fruit arc-en-ciel` (clears one type). Cascades multiply score. Overlays: `gelée` (jelly, cleared by collecting on top; double layers are purple), `cageots` (crates, no tile can sit on them, broken by clearing tiles next to them — two hits for a `.cracked` one), and irregular board shapes (`voids` cells).

**Level generation (`src/levels.js`) is fully deterministic** — `mulberry32(hash32(n))` seeded per level number, so every visitor sees the same 60 levels, and nothing is stored. Per level: `tier` (difficulty badge/chili, from `n%5/8/9/13` patterns), `arche` (score / jelly / collect / blocker or a mix, from `(n-17)%7`), a shape, an objective set, then:

- **Objective shrink:** objectives are weighted (`jelly 1.5`, `collect 1.15`, `blocker 4` per unit). If the total exceeds `WORK_CAP = 18 + round(n*0.25)`, jelly/crates are reduced proportionally so a level is never mathematically impossible.
- **Moves:** `round(max(10, 24 - round(n*0.23)) + work)`, clamped to `[12, 48]` (score levels get a flat 22–26). The `24 - 0.23n` term shrinking while `work` grows is where the difficulty ramp comes from.
- **Score levels:** target = `moves × ppmFor(types) × f × (0.62 + 0.38·area)`. `PPM_BY_TYPES = {5:200, 6:115, 7:70}` are *measured* points-per-move of a decent player, so **recalibrate them with `GAME.__debug.probe` if the board/type generation changes**.
- **Stars:** thresholds are `[target, 1.32·target, 1.75·target]`, displayed as the star bar + 3 stars.

**Progression.** `window.GAME` persists `{stars:{n:count}, boosters:{hammer,shuffle,moves}, best, plays}` in the kv-plugin (`root.kv.saga.get("saga")`) with a `localStorage("saga_meta")` fallback/shortcut. Boosters: Marteau (tap a cell to smash it), Mélanger (reshuffle), 5 coups. +2 boosters per win. Level *n* is unlocked when *n-1* is completed.

**Balance harness (headless).** The logic core runs without DOM/timers, so `window.GAME.__debug` can play thousands of games: `simulate(n, {})`, `balance(from, to, runs)`, `probe([{types, moves}], runs)`, plus `def/meta/setMeta/startLevel/setScore/setMoves/setGrid/swap/moves/reshuffle`. Measured ramp (10 runs/level): overall **86 % win**, ~0.98 stars, by decade 93/94/87/88/78/73 %.

Caveat: the bot only ever plays *immediate* matches (highest `moveValue`), it cannot set up a move. On jelly levels it therefore sometimes stalls with 1–3 jelly cells left that have no immediate match through them — its numbers are a **pessimistic lower bound**, not a bug in those levels. Don't "fix" levels by inflating moves; a human clears them by setting up the final match.

**Verification gotcha (important).** In the editor preview `document.hidden === true`, which freezes the document animation clock: every element whose visibility depends on an animation rests on its *first* keyframe (`freshIn` = `scale(.15)`, `jellyIn`/`blockIn` = `opacity:0`), so the board looks empty in screenshots. Before capturing or judging the board, run `document.getAnimations().forEach(a => { try { a.finish(); } catch (e) { a.cancel(); } })` and set `img.loading="eager"` on all images (lazy ones never load while hidden, which makes the snapshot helper hang). The live game is unaffected.



Avatars were generated with a **family-differentiated style system** (`scratch/futurocite/gen_images.js` — rebuild harness; scratch is ephemeral, so treat this as historical). 17 style families (verger, rouges, agrumes, coque, melon, racines, feuilles, choux, tiges, cucurbitacées, alliacées, champignons, légumineuses, soleil, aromatiques, tropical, heritage) each with its own kawaii style words + pastel background tint + scene; poses rotate per product. Banners reuse the same family scene + rotating mood/lighting so every product has its own coherent, varied background.

**Avatar precision pass (36 sprites reworked).** Several sprites read wrong or were confusable (plantain looked like an avocado, carambole like a pear, melon like a watermelon, haricot vert like a green blob, cassis/groseille like raspberries, asperges like cacti, etc.). Those were regenerated with a *silhouette-first* prompt method, which is the recipe to reuse:1. Describe the produce by **shape/proportion/colour/texture**, not just its name ("a fanned bundle of three narrow pencil-thin green asparagus spears, each with a uniform slender shaft, tiny flat triangular bracts, small cone-shaped buds"), then name it.
2. Add **negatives for the lookalikes** the model confuses it with (`watermelon, green stripes` for melon; `avocado, pear` for plantain; `raspberry, blackberry, drupelets` for cassis/groseille; `cactus, aloe, thick fat stems` for asparagus).
3. Append the **shared kawaii style block** verbatim (thick dark-brown outline, thin white sticker outline, glossy cel shading, big sparkly eyes, blush, stubby limbs, soft oval shadow, flat pastel background, sparkles, square centred composition) so new sprites match the old set.
4. Verify by building a labelled montage of the outputs (OffscreenCanvas in `execute_js`) and comparing against **reference photos** (`https://fr.wikipedia.org/w/api.php?action=query&prop=pageimages&pithumbsize=420&titles=…`) — the model has strong priors (any "melon" becomes a watermelon), so one or two iterations per item are normal, and for carambola the reliable trick is to draw the **star-shaped slice** rather than the whole fruit.
5. Generate with `text-to-image-plugin` at `512x512` (`root.generateImage({prompt, negativePrompt, resolution})`) and upload the `dataUrl` with `upload-plugin` (`root.uploadPlugin(blob)`), then write the URL into `src/data/avatars.js`. Both plugins must be imported in `main.pjs` **only while doing this** — `text-to-image-plugin` puts an ad on the generator for logged-out users, so remove the imports afterwards.

The final prompt text for all 36 reworked avatars (with their URLs) is kept in `src/tools/avatar-prompts.json` so any of them can be regenerated/tweaked later.

The **banners** for those same 36 products were regenerated too (a stale banner next to a fixed avatar is very visible on the detail page): same produce description + `shown as a cute cartoon character standing in {scene}` where `{scene}` rotates deterministically through six scene templates (garden path, orchard clearing, wooden market stall, berry thicket, greenhouse corner, meadow) at `768x512`. `src/tools/avatar-prompts.json` holds the produce descriptions used for both.

## Notes / gotchas

- The platform injects a global `button:not([disabled]){color:inherit}` reset (specificity 0,1,1). Any plain class selector setting button text color (e.g. `.hh-btn`, `.mb-primary`) loses to it — write `button.hh-btn` / `button.mb-primary` instead (that's why the hero CTA and modal buttons use `button.` prefixes).
- The snapshot/capture tool falls back to html2canvas when snapdom can't decode the page; html2canvas can't render cross-origin `user.uploads.dev` images, CSS masks, or conic-gradients, so screenshots may show gray tiles / no rainbow / no strip fade even though the live browser renders them fine — verify with DOM checks (image `complete`/`naturalWidth`, computed styles) before trusting a vision pass that disagrees with the live DOM.
- Write tool aborts on large single writes — author big files via `execute_js` `fs.writeTextFile` in chunks, or keep files small.
- Avatars rely on matching product names exactly (`AVATARS[p.n]`); product names were trimmed of trailing spaces.
- The old 1:1 reproduction app (104 products inline + FUTUROCITE_LOCAL_HTML) was fully replaced by this shell; all original data lives in `src/data/products.js`.
- Responsive: grid `auto-fill minmax(118px,1fr)` on phone, game board re-measures from `.board-wrap` width on tab enter/resize (never from the board's own width, or it won't shrink).
